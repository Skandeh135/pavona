# usbdev Feature Report

## Feature List
<table class="verification_report_table">
  <thead>
    <tr>
      <th>Features</th>
      <th>Descriptions</th>
    </tr>
  </thead>
  <tbody>
    <tr id="usbdevbuffermemory">
      <td>USBDEV.BUFFER.MEMORY</td>
      <td>usbdev presents a conventional 512-entry 32-bit RAM on the memory busthat supports read/write operations for receiving and sending packets overthe USB. Writing and reading of partial words is not supported.</td>
    </tr>
    <tr id="usbdevconnpin_config">
      <td>USBDEV.CONN.PIN_CONFIG</td>
      <td>Support for different pin configurations; pin flipping, transmission andreception modes.</td>
    </tr>
    <tr id="usbdevconnpullup">
      <td>USBDEV.CONN.PULLUP</td>
      <td>Assertion and removal of pull up resistor indicating Full Speed devicepresence on the USB.</td>
    </tr>
    <tr id="usbdevconnref_pulse">
      <td>USBDEV.CONN.REF_PULSE</td>
      <td>Generation of a reference pulse in response to Start Of Frame packetreception, to synchronize the device clock with that of the host controller.</td>
    </tr>
    <tr id="usbdevconnreset">
      <td>USBDEV.CONN.RESET</td>
      <td>usbdev reset and the ability to empty the Av and Rx FIFOs. Required foradapting to polarity of SBU connections on USB-C cables.</td>
    </tr>
    <tr id="usbdevconnvbus">
      <td>USBDEV.CONN.VBUS</td>
      <td>Detection of VBUS/SENSE signal from the host controller, indicating aconnection and/or supplying power.</td>
    </tr>
    <tr id="usbdevpoweraon">
      <td>USBDEV.POWER.AON</td>
      <td>Handover of the USB to the AON module that handles Wake signaling.</td>
    </tr>
    <tr id="usbdevpowerresume">
      <td>USBDEV.POWER.RESUME</td>
      <td>Detection of Resume Signaling from the host controller.</td>
    </tr>
    <tr id="usbdevpowersuspend">
      <td>USBDEV.POWER.SUSPEND</td>
      <td>Detection of Suspend request from the host.</td>
    </tr>
    <tr id="usbdevpowertoggle_restore">
      <td>USBDEV.POWER.TOGGLE_RESTORE</td>
      <td>Save and restore Data Toggles for all IN and OUT endpoints.Resuming from Deep Sleep requires the ability to restore the Data Togglesto an arbitrary state. (Requires prod-only RTL changes.)</td>
    </tr>
    <tr id="usbdevpowerwake_bus_reset">
      <td>USBDEV.POWER.WAKE_BUS_RESET</td>
      <td>Wake from Sleep in response to Bus Reset from host.</td>
    </tr>
    <tr id="usbdevpowerwake_disconnect">
      <td>USBDEV.POWER.WAKE_DISCONNECT</td>
      <td>Wake from Sleep in response to Disconnection.</td>
    </tr>
    <tr id="usbdevpowerwake_resume">
      <td>USBDEV.POWER.WAKE_RESUME</td>
      <td>Wake from Sleep in response to Resume Signaling.</td>
    </tr>
    <tr id="usbdevtransferbulk">
      <td>USBDEV.TRANSFER.BULK</td>
      <td>Bulk Transfer streams.</td>
    </tr>
    <tr id="usbdevtransfercontrol">
      <td>USBDEV.TRANSFER.CONTROL</td>
      <td>Support for Control Transfers/Endpoints other than the Default Control Pipeat Endpoint Zero.</td>
    </tr>
    <tr id="usbdevtransfercontrol_rx">
      <td>USBDEV.TRANSFER.CONTROL_RX</td>
      <td>Reception of packets in Control Transfers from the host controller.</td>
    </tr>
    <tr id="usbdevtransfercontrol_tx">
      <td>USBDEV.TRANSFER.CONTROL_TX</td>
      <td>Transmission of response packets in Control Transfers from the host.</td>
    </tr>
    <tr id="usbdevtransferendpoints">
      <td>USBDEV.TRANSFER.ENDPOINTS</td>
      <td>Use of multiple endpoints in communication with the host controller.</td>
    </tr>
    <tr id="usbdevtransferinterrupt">
      <td>USBDEV.TRANSFER.INTERRUPT</td>
      <td>Support for Interrupt Transfers and Endpoints.</td>
    </tr>
    <tr id="usbdevtransferisochronous">
      <td>USBDEV.TRANSFER.ISOCHRONOUS</td>
      <td>Support for Isochronous Transfers and Endpoints.</td>
    </tr>
  </tbody>
</table>
